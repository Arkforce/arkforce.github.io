Case study / Storage automation

Hybrid Infrastructure Automation

Automated storage expansion across VMware, Azure, and AWS through one repeatable operating pattern.

01 Git request reviewed change
→
02 Bitbucket pipeline trigger
→
03 Automation Ansible / AWX / PowerShell
→
VMware Azure AWS
Problem

Routine storage expansion was a manual, platform-specific task across VMware, Azure, and AWS. A single server change regularly consumed more than 30 minutes, and repeating the process across multiple systems increased operational toil and the opportunity for inconsistent execution.

Delivered

I built reusable workflows using Ansible/AWX, PowerShell, and pipeline-driven execution. Engineers supplied target systems and change parameters, and the automation ran the appropriate platform-specific workflow for individual or multi-server changes.

Result

Routine execution dropped from 30+ minutes to approximately 2–5 minutes per server—a 6–15× improvement with substantially less repeated manual effort.

ScopeVMware / Azure / AWS

Routine storage-expansion execution measured at 30+ minutes before automation and approximately 2–5 minutes afterward, per server.

Case study / Declared state

Configuration as Code

Implemented Git-managed configuration for server access, DNS, and DHCP, with automated drift reconciliation.

Declared state → Git review → Automated execution → Drift reconciliation
Problem

Manual configuration changes made it difficult to establish the intended state of a system and keep that state consistent over time.

Delivered

I moved supported configuration into version-controlled definitions and connected them to automated execution. Git became the source of truth, with reviewable history and comparison of live configuration against declared state.

Result

Supported configuration became repeatable and traceable. Engineers could inspect intended state, review changes, and reconcile drift through a consistent workflow.

ScopeAccess / DNS / DHCP

Git-managed definitions and the reconciliation lifecycle; production configuration remains omitted.

Case study / Guided investigation

AI-Assisted Incident Investigation

Combines operational context to summarize incidents, generate hypotheses, and recommend investigation steps while keeping the response decision with the engineer.

Connected sources Splunk / Grafana / Microsoft Graph / AWS → Incident summary → Hypotheses → Recommended checks → Engineer decision
Problem

Incident investigation required gathering information from separate systems before an engineer could assess the evidence and decide what to do next.

Delivered

I built an AI-assisted investigation workflow that brings together operational context from Splunk, Grafana, Microsoft Graph, and AWS. It summarizes incidents, generates hypotheses about possible causes, and recommends investigation steps. Engineers review the available evidence, validate the hypotheses, and decide what action to take.

Result

The workflow provides a shared starting point for investigation. The engineer remains responsible for interpreting the evidence and choosing the operational response.

ScopeContext → Analysis → Engineer review

Incident summaries, possible-cause hypotheses, and recommended investigation steps.
