01 / PLATFORM & IDENTITY

AWS IAM Role Factory

A repeatable interface between an access request and an AWS identity. Shared catalogs define the available trust and permission profiles.

TERRAFORM / YAML / AWS IAM PERSONAL PROJECT CODE AVAILABLE
  1. YAML request
  2. Catalog validation

The problem

Creating IAM roles individually makes trust relationships, permission attachments, and ownership metadata harder to keep consistent. A reviewed request should carry enough context to generate a predictable result.

What I built

A Terraform factory that reads YAML requests and centrally managed trust and permission catalogs. It creates IAM roles, policy attachments, customer-managed policies, EC2 instance profiles where appropriate, and ownership tags. Requests are scoped to the account associated with the active AWS credentials.

The architecture decision

Keep the request interface small and put policy construction in shared catalogs. Requesters select approved profile names; the factory validates account formats, duplicate targets, ownership, change tickets, profile references, and session duration.

Boundaries that matter

This repository creates IAM resources only. Saved plans must not be reused after switching AWS credentials or accounts. The repository documents lab-specific provider workarounds that need reassessment before production use.

The result

One reviewable pattern for role delivery, with redacted examples for service trust, Bitbucket OIDC, and Grafana Cloud. The preview demo illustrates a small part of the request-to-output experience.
