AI-Assisted Incident Investigation

Operational context becomes an incident summary, possible-cause hypotheses, and recommended investigation steps for engineer review.

SPLUNK / GRAFANA / MICROSOFT GRAPH / AWS ENGINEER REVIEWED
  1. Connected sources
  2. Incident summary
  3. Hypotheses & checks
  4. Engineer decision

The problem

Incident investigation starts with scattered context. Before engineers can reason about a cause, they need to gather information from telemetry and operational systems.

What I built

An AI-assisted workflow connecting context from Splunk, Grafana, Microsoft Graph, and AWS. It summarizes incidents, proposes possible causes, and recommends investigation steps.

Where the engineer stays involved

The engineer reviews available evidence, validates or rejects hypotheses, and decides the operational response. A recommended check is an investigation aid; it is not a verified root cause.

The result

A shared starting point for investigation, bringing operational context and recommended next steps into one workflow. The engineer validates hypotheses and chooses the response.

WORKFLOW OUTPUTS

01  Incident summary
    What happened and relevant context

02  Hypotheses
    Possible causes to investigate

03  Recommended checks
    Next steps for engineer review

The workflow produces these three outputs for engineer review.
